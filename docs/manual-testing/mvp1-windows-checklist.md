# MVP1 — ручная валидация на Windows

Выполняется на реальной Windows-машине с установленным официальным клиентом
Tiles Survive. Каждый пункт закрывает риск, который нельзя проверить
юнит-тестами на fake-реализациях (см. design doc, раздел 7).

1. `uv sync` на Windows ставит `pywin32` без ошибок.
2. `uv run python -m tiles_survive_automation.app` открывает GUI, в
   выпадающем списке окон виден запущенный клиент Tiles Survive.
3. Выбрать окно игры, нажать Record, выполнить в игре: обычный клик, клик
   правой кнопкой, drag (например, перетаскивание в инвентаре), прокрутку
   колёсиком, нажатие клавиши. Нажать Stop, сохранить как Rule с именем.
4. Проверить, что в `data/templates/<rule_id>/` появились PNG для каждого
   клика, а в `data/screenshots/` — полные скриншоты окна на момент клика.
5. Нажать Play на сохранённом Rule — все действия должны воспроизвестись в
   тех же местах интерфейса игры (лог должен показывать `confidence` близко
   к 1.0 для visual-совпадений).
6. Свернуть окно игры перед Play — приложение должно активировать его через
   `SetForegroundWindow` перед выполнением первого шага.
7. Передвинуть окно игры на экране между Record и Play — relative-координаты
   и visual-поиск должны сработать одинаково (клиентские координаты, а не
   абсолютные экранные).
8. Во время Play нажать F9 — воспроизведение должно немедленно остановиться,
   зажатая (если была) кнопка мыши — отпуститься, даже если фокус в этот
   момент был в игре, а не в приложении.
9. Намеренно сломать один template (переименовать/удалить файл) и запустить
   Play — приложение должно остановиться на этом шаге, сохранить screenshot
   ошибки и показать пользователю, какой именно step не прошёл (Strategy 3).
10. Проверить многомониторную/масштабированную (125%/150% DPI) конфигурацию
    экрана — координаты клика не должны расходиться с реальным положением
    элементов интерфейса.

Отметить каждый пункт как пройденный/непройденный с комментарием перед тем,
как считать MVP1 завершённым.
